## Objective

Persist a role-filtered **alert type** catalog (seed four BR-05 codes; admin create/deactivate) as an API façade without merging Andon / `alertas` / `notifications` schemas.

## Context

Catalog is a shared capability (ADR-013). Threshold **values** stay in module stores. This EWO is HTTP + overlay + swimlane tests only.

## Scope

- Seeded registry: `MTTO_VENCIDO`, `STOCK_BAJO`, `SALUD_UMBRAL`, `FLOTA_SIN_REGRESO`.
- Overlay schema `alert_catalog.tipo` (`active`, extra admin types).
- HTTP under `/configuracion/alertas` with `X-Role` swimlane (BR-03).
- Port `AlertTypeActivePort` for later emit-gate (EWO-003).
- `GET`/`PATCH` umbrales for `FLOTA_SIN_REGRESO` via `AlertasService` (schema `alertas`).
- MODULE umbrales: authorize swimlane; delegate to owning services / existing module HTTP.

## Out of Scope

- WhatsApp / dual-stack notify factories.
- Merging schemas or moving `min_qty` / Andon umbrales / Salud config into `alert_catalog`.
- UI Configuración (EWO-002).
- Wiring emit-time gate in engines (EWO-003) beyond exporting the port.
- Declaring a new confirmed Bounded Context.
- GPS, multi-almacén, OC, preferencias por usuario.

## Domain Rules

- BR-01–BR-03, BR-05 metadata, BR-08 (`WO-` prefix forbidden on codes).
- Inactive: hidden from non-admin lists; Admin still sees them.
- Unknown or not-visible `code` → 404 (do not leak the other family’s payloads).
- Unauthorized mutation → 403.

## Dependencies

SPEC approved; ADR-013 accepted. Existing `AlertasService`, Andon umbrales, Inventario items, Salud config.

## Acceptance Criteria

### AC-01
Given seed BR-05  
When `SUPERVISOR` `GET /configuracion/alertas`  
Then only `family=MTTO` types; no `FLOTA_SIN_REGRESO`.

### AC-02
Given same seed  
When `LOGISTICA` lists  
Then only `family=FLOTA`.

### AC-03 (API half)
Given `ADMIN_DIRECTIVO`  
When they `POST` type `X` and deactivate `MTTO_VENCIDO`  
Then `X` is listed for the matching family; `MTTO_VENCIDO` is `active=false` (emit suppression is EWO-003).

### AC-04
Given `SUPERVISOR`  
When they `POST` or `PATCH` type active  
Then 403.

### AC-07 / AC-08 (API)
Given `SUPERVISOR` mutating `FLOTA_SIN_REGRESO` umbrales via catalog API → 403.  
Given `LOGISTICA` mutating Andon / stock / Salud via catalog API → 403.

### AC-12
When schemas are listed  
Then `andon`, `notifications`, and `alertas` (sin-regreso) still exist; catalog overlay is a separate schema.
