## Objective

Ship **Configuración → Alertas** (pattern 3 + dialog 7) filtered by role, with Admin create/deactivate affordance, and send `/flota/alertas` to that screen (Flota type). Product labels **Alertas** on config and inbox/campanita.

## Context

Depends on EWO-001 HTTP. Visual system: `docs/design/*`. Do not invent a settings sidebar.

## Scope

- Route `/configuracion/alertas`; nav item **Configuración** for `SUPERVISOR`, `ADMIN_DIRECTIVO`, `LOGISTICA`.
- Role-filtered table; Admin **Nueva alerta**; row opens type dialog (EWO-003 fills threshold fields; this EWO must show create/deactivate + list).
- Redirect `/flota/alertas` → `/configuracion/alertas?code=FLOTA_SIN_REGRESO`.
- Flota tablero secondary link, Andon “Configurar alertas”, Unidades admin menu: point at the catalog (not a parallel IA).
- Inbox H1 + campanita accessible name: **Alertas**. Keep path `/notificaciones`.
- Screenshots per UX spec / user list.

## Out of Scope

- `api/src` except if a DTO field is missing from EWO-001 (prefer fix there).
- WhatsApp. Schema merge. Playwright.
- Redesigning Andon board (nav stays **Alerta**).
- Visit WO wizard.

## Domain Rules

BR-02/03 visibility. AC-09 language. Inactive hidden from non-admin.

## Dependencies

EWO-001 API. UX spec. Existing `PageHeader`, `DataTable`, `Dialog`, `Button`, `Badge`, `Field`.

## Acceptance Criteria

### AC-01 UI
Supervisor list shows only MTTO family types.

### AC-02 UI
Logística list shows only Flota types.

### AC-03 UI
Admin sees all types plus create/deactivate controls.

### AC-09
Config and inbox/campanita primary labels use Alertas.

### AC-10
`/flota/alertas` reaches Configuración → Alertas (Flota type) without a second form model.

## Testing Requirements

- Visual QA: subagent `ux-auditor` (separate pass).

### Compatibility

### Security
