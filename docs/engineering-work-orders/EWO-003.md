## Objective

Wire per-type threshold editors (Andon, Inventario dual, Salud, Flota CATALOG) through Configuración → Alertas, and **suppress new inbox items** when the type is inactive (check at emit time).

## Context

EWO-001 overlay + EWO-002 shell. Emitters keep evaluating in their modules (BR-04). Inbox adapters stay the delivery seam.

## Scope

- Dialog editors bound to `code`:
  - `MTTO_VENCIDO` → Andon km/días (persist `andon.umbrales`; Supervisor allowed via catalog / `PATCH /andon/umbrales`).
  - `STOCK_BAJO` → per-ítem “Avisar si quedan”; Existencias dialog remains.
  - `SALUD_UMBRAL` → alert enabled + thresholds; dimension weights stay on Unidades Admin salud dialog. `PUT /salud/config` remains Admin-only (H14); Supervisor writes Salud **alert** fields via catalog façade.
  - `FLOTA_SIN_REGRESO` → localH / foraneoH via catalog → schema `alertas`.
- `AlertTypeActivePort.isActive(code)` immediately before **new** inbox ingest: Andon `onAbierto`, Inventario `onStockBajo`, Salud `onOpened`, Flota `onAbierto`.
- Expire/clear/resolve still run if the condition clears.
- Fail closed: if CATALOG sin-regreso config cannot be read, do not emit.

## Out of Scope

- Changing WhatsApp `NotifyPort` / dual-stack factories (AC-11).
- Deleting historical inbox rows on deactivate (BR-06).
- Generic rules engine. Per-user prefs. GPS.

## Domain Rules

BR-04, BR-05, BR-06, BR-07. Concurrent deactivate + emit: re-check `active` at emit. Inventario UI may still edit `min_qty` while `STOCK_BAJO` is inactive; only inbox is gated.

## Dependencies

EWO-001, EWO-002. Existing ports: `AvisoInboxPort`, `StockAlertPort`, `HealthAlertPort`, `FlotaSinRegresoPort`.

## Acceptance Criteria

### AC-03 (emit)
Given Admin deactivated `MTTO_VENCIDO`  
When Andon would open an aviso  
Then no **new** inbox item for that code (Andon board may still open the aviso; WA unchanged).

### AC-05
Supervisor changes Andon km/días from the catalog entry → values in Andon store; later evaluation uses them.

### AC-06
Logística edits sin-regreso hours under Configuración → Alertas → persist in `alertas`; `/flota/alertas` not required.

### AC-07 / AC-08
UI hides the other family’s editor; API 403 as EWO-001.

### AC-11
`ANDON_NOTIFY_PROVIDER` default still `noop`; both notify factories present; this EWO does not edit them.

## Testing Requirements

- Unit: active-gate (`K5`); CATALOG persist (`K6`).
- e2e: deactivate then stock/andon/flota ingest does not add a new inbox row; PATCH umbrales by role.
- `cd api && npm test && npm run test:e2e`
- UI: proof-ui threshold dialog screenshots.

## Constraints

### Architecture

No writes from catalog into `andon.*` tables except through AndonService. No `andon.*` for stock/salud/flota. Optional injection so existing engine unit tests default to active.

### Compatibility

H14: `PUT /salud/config` Supervisor still 403. L12: Supervisor still 403 on `/logistica/alertas` (catalog is the Logística editor).

### Security

Do not return MTTO umbral payloads to Logística or Flota payloads to Supervisor.

### Performance

One extra `isActive` read per emit (tiny table).

### UX

Copy from UX spec; no `t_km` / `min_qty` in labels.
