## Objective

Make **Configuración → Alertas** read as Team Mex ops UI: clear menu identity vs nav **Alerta** (Andon board), no engineering jargon in the list, hierarchy and tokens from the design system, Visual QA gated on those briefs — not only role swimlanes.

## Context

**IA locked for this EWO:** keep the **hub** at Configuración → Alertas (SPEC Approved). Do **not** relocate the catalog to Unidades/Stock.

Deferred (out of this EWO): product rewrite that would make Unidades/Stock the *only* alert config surface (brief-first model). Dual editors for Inventario `min_qty` remain allowed.

Post–PR #67 audit findings to fix:
1. Weak identity: Configuración underlined but no settings/subnav story; collision with top-nav **Alerta**.
2. Technical slugs (`MTTO_VENCIDO`, …) competing in the list.
3. Column “dónde se edita” / architecture copy for operators.
4. Generic dense table / status noise (green ACTIVA on every row).
5. Design-system briefs were cited in EWO-002 but not enforced as Visual QA Must.

## Scope

- **Menu identity**
  - Keep top-nav **Alerta** = Andon board (ops).
  - Configuración → **Alertas** = catalog (settings). Add clear in-page identity: PageHeader H1 **Alertas** (navy 20/600), lede that answers “tipos que configuras aquí / lo que llega a la campanita”, and either a Configuración subnav (Alertas as active item) **or** an equivalent breadcrumb/location cue that is not a generic SaaS settings sidebar.
  - Do not invent a fifth page pattern; justify any new chrome against PAGE_PATTERNS.
- **List content**
  - Primary cell: product name only (Spanish taller).
  - Stable `code` only as muted 12px `.mono` secondary line **or** Admin-only / dialog — never as the visual equal of the name.
  - Remove or replace “dónde se edita” / “En el módulo” / “En este catálogo” with taller copy (e.g. omit column; or short “Se ajusta en …” only if it helps work).
  - Family / owner: keep if useful; demote to P2 muted.
  - Estado: do not paint green **Activa** on every row. Prefer no badge when all active; **Inactiva** muted for Admin only when inactive.
- **Actions**
  - Admin: one orange CTA **Nueva alerta** (`default`).
  - Supervisor / Logística: rows are the action — zero orange on the list.
  - Dialog: **Guardar** outline/tertiary if Nueva alerta already owns orange; **Cancelar** secondary; **Desactivar** `dangerSoft` — never a second solid orange.
  - Copy: never `umbral`, `t_km`, `t_días`, `min_qty`, “regla” in UI strings (per alertas-copy brief).
- **Components / tokens**
  - Reuse `PageHeader`, `DataTable` / existing list chrome, `Dialog`, `Button`, `Badge`, `Field` from `web/src/components/ui`.
  - Tokens from `globals.css` / DESIGN_SYSTEM only (CTA `#EA7515`, shell `#24284D`, page `#F3F3F3`, radius 6, borders not soft shadows).
  - Density: page padding 12–16; no marketing whitespace; no Lucide per row.
- **Proof**
  - Replace/update PNGs under `docs/screenshots/alert-catalog/` for Supervisor, Logística, Admin list, Admin alta, one threshold dialog, inbox label if touched.
  - Visual QA pass must explicitly check the design-system Musts above (separate from swimlane ACs).

## Acceptance Criteria

### AC-01 — Menu identity
Given Admin or Supervisor on `/configuracion/alertas`  
When the page is shown  
Then H1 is **Alertas**, location under Configuración is obvious in ≤5s, and top-nav **Alerta** is not required to understand “this is the catalog”.

### AC-02 — No engineering primacy in list
Given any role’s catalog list  
When scanning the primary column  
Then the product name dominates; codes are muted secondary or absent from the default scan path; no `umbral` / `t_km` / schema jargon.

### AC-03 — Column / hierarchy cleanup
Given the catalog table  
When compared to pre-polish  
Then architecture column “dónde se edita” is gone or replaced with taller-safe copy; status does not flood every row with green Activa.

### AC-04 — Button grammar
Given Admin list  
When viewing CTAs  
Then exactly one solid orange control (**Nueva alerta**). Supervisor/Logística lists have none.

### AC-05 — Design-system Visual QA
Given proof screenshots  
When `ux-auditor` (or equivalent) reviews  
Then the PR notes pass/fail against anti-generic, nav-vs-filter, alertas-copy, DESIGN_SYSTEM, and PAGE_PATTERNS 3+7 — swimlane-only OK is insufficient.

### AC-06 — Swimlanes preserved
Given Supervisor / Logística / Admin  
When opening the catalog  
Then family visibility and Admin-only create/deactivate from SPEC remain true.
