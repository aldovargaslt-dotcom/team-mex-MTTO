## Objective

Make **Configuración → Alertas** scannable as a **configuring** task: grouped by Área, each row showing product name + **Cuándo avisa** summary, clear row affordance — without turning it into cards, a SaaS settings sidebar, or a monitoring dashboard.

## Context

SD Accepted Option B (2026-09-22): keep table; enrich rows; group by Área (Mantenimiento / Flota); drop Dueño from list; Admin-only **Nueva alerta**.

Pain after EWO-004: list still reads as generic metadata (Alerta · Área · Dueño). Área/Dueño often redundant; useful threshold values hidden until dialog open; weak “what do I do here?”.

IA remains locked: hub stays Configuración → Alertas.

## Scope

- **Grouping:** Admin list sections `Mantenimiento` then `Flota`. Supervisor / Logística: single family — one section or no empty group chrome.
- **Columns:** **Alerta** (P0 product name) | **Cuándo avisa** (P1 taller Spanish summary from live thresholds) | row affordance (`›` or equivalent, not Lucide-per-row icon set).
- **Remove from list:** Dueño column; any architecture / “dónde se edita” residue.
- **Área:** group heading when multi-área; do not repeat as a competing primary column when grouped.
- **Lede:** task-oriented (adjust when it alerts / tap a row). Role variants per UX spec.
- **Summaries:** derive from existing threshold/API payloads already used in the type dialog. Do **not** invent numbers. Prefer short taller copy (e.g. `5 000 km o 90 días`, `Local 8 h · Foránea 24 h`, `Según mínimo en existencias`). If a type has no configurable thresholds yet, use a honest muted fallback (e.g. `Sin ajuste en lista`) — escalate only if product copy is unclear.
- **After save:** refresh the row’s Cuándo avisa summary.
- **Tokens / grammar:** preserve EWO-004 rules (one orange Admin, zero orange other roles, no Activa green flood, Inactiva Admin-only when inactive, dialog Guardar outline when Nueva alerta owns orange).
- **Proof:** update PNGs under `docs/screenshots/alert-catalog/` for Admin (grouped), Supervisor, Logística, one threshold dialog; Visual QA against Experience Context anti-pattern checklist v0.1.

## Out of Scope

- API / schema / ADR-013 façade redesign.
- New threshold fields or business rules.
- Merging Andon / alertas / notifications schemas.
- WhatsApp / dual-stack notify.
- Relocating hub to Unidades/Stock-only.
- Card grid, SaaS settings sidebar, KPI strip, Lucide-per-row.
- Renaming top-nav **Alerta** or the visit **WO** wizard.
- Playwright.

## Acceptance Criteria

### AC-01 — Grouping
Given Admin on `/configuracion/alertas` with both families present  
When the list renders  
Then types appear under **Mantenimiento** and **Flota** section headings (order: Mantenimiento then Flota).

### AC-02 — Single-family chrome
Given Supervisor or Logística  
When the list renders  
Then only their family types show, and there is no empty second group / no fake multi-área theater.

### AC-03 — Cuándo avisa column
Given any role’s list  
When scanning a row  
Then P0 is the product name and P1 is a **Cuándo avisa** summary in taller Spanish derived from live data (not codes, not `umbral` / `t_km` / `min_qty`).

### AC-04 — Dueño removed
Given the catalog list  
When compared to pre-EWO-005  
Then there is no **Dueño** column on the list (Dueño may remain Admin-only inside create/edit dialog if already present).

### AC-05 — Affordance + lede
Given the page  
When viewed without opening a dialog  
Then it is obvious that a row opens configuration (lede and/or `›`), and Admin still has exactly one solid orange (**Nueva alerta**); other roles have zero orange on the list.

### AC-06 — Design-system / Experience gate
Given proof screenshots  
When Visual QA runs against Experience Context v0.1 checklist  
Then PASS: configuring task, no cards/sidebar/KPIs/Lucide-per-row, no Activa flood, dialog button grammar intact. Swimlane-only OK is insufficient.

### AC-07 — Swimlanes preserved
Given Supervisor / Logística / Admin  
When opening the catalog  
Then family visibility and Admin-only create/deactivate from SPEC remain true.

### Security

### Performance
