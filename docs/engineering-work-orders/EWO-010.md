## Objective

Tras aprobación de producto, conservar la orientación del Supervisor y aclarar los estados/alertas existentes sin redefinir ownership ni reglas de negocio.

## Scope

- Ejecutar únicamente AC-01 a AC-10 del SPEC aprobado.
- Mantener Inicio como cola de excepciones; Órdenes es el único panel de trabajo.
- Conservar alertas mientras su condición fuente esté abierta; visto no debe expirarlas.
- Documentar cualquier propuesta de lectura de cola backend como trabajo separado de shaping/ADR.

## Out of Scope

- Prioridad, vencimiento, asignación individual, nuevos estados, Flota Logística, schemas y notify dual-stack.

## Domain Rules

- Un borrador es una visita `BORRADOR` compartida; no existe ownership individual.
- Solo `SUPERVISOR` y unidad `ACTIVA` permiten crear visita.
- `Enterado` de Andon no resuelve la alerta; Salud e Inventario conservan sus propios ciclos.

## Dependencies

- Entorno Docker/API con semilla para pruebas UI y móvil.
- Si se cambia la lectura N+1 de Órdenes: shaping, SPEC y ADR antes de código.

## Acceptance Criteria

Referencia única: [SPEC-SUPERVISOR-EXPERIENCE-001](../specs/supervisor-experience-v0.md) AC-01 a AC-10.

- `cd web && npm run lint`
- `cd web && npm run build`
- proof-ui: flujo Supervisor con semilla en desktop 1440 y móvil 390; PNG declarados en UX spec.
- Si cambia backend autorizado: pruebas focales + `cd api && npm test && npm run test:e2e`. No ejecutar `api lint --fix`.

### UX

Una acción primaria por vista, excepción antes que dashboard, Spanish copy, 44 px en móvil.
