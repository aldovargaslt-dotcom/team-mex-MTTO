## Objective

Permitir al Supervisor crear o recuperar una orden desde `/ordenes`, continuar el wizard con retorno preservado y hacer evidentes/accesibles las capturas de piezas y fotos.

## Scope

- Dialog desktop/sheet móvil con unidad activa, chofer, km y tipo.
- Borrador existente y carrera convertidos en `Continuar orden`.
- Estado de cola/filtros/orden en URL y `returnTo` interno.
- Mapeo compartido `PREDICTIVO` → `Preventivo` en web.
- Disclosures accesibles de piezas/fotos y lectura para cerradas.

## Out of Scope

- Ficha de unidad, API adicional, catálogo como destino intermedio, kanban, estados/prioridad/SLA, Flota y cambios a foto de unidad.

## Domain Rules

- La UI consume el contrato de ADR-015; no infiere autoridad desde un precheck.
- Solo Supervisor crea; Admin conserva cerradas en lectura.
- Máximo ocho fotos y reglas actuales de piezas permanecen.

## Dependencies

- EWO-011 verificado y contrato API disponible.

## Acceptance Criteria

SPEC AC-O01 y AC-O05–O08; AC-O02–O04 se verifican aquí como integración UI, sin duplicar autoridad API.

## Testing Requirements

- `cd web && npm run lint`
- `cd web && npm run build`
- Click-through Supervisor en 390×844, 1024×768 y 1440×900; teclado, back/forward y carrera simulada/real.
- Screenshots: `ordenes_nueva_sheet_m390.png`, `ordenes_nueva_dialog_d1440.png`, `ordenes_borrador_existente.png`, `ordenes_captura_pieza_foto.png`.
- Impeccable mechanical detector once after UI completion; then `proof-ui`; separate `ux-auditor` pass.

## Constraints

### Architecture

No nuevo endpoint de cola; usar lecturas existentes y contrato de EWO-011.

### Compatibility

Preservar links actuales a órdenes y wizard, incluida lectura Admin.

### Security

Allowlist para `returnTo`; nunca navegar a URL arbitraria.

### Performance

No agravar deliberadamente el N+1 de cola; si crear el selector exige una lectura nueva, escalar antes.

### UX

Una acción primaria, hits ≥44 px, foco restaurado, estados inline, Spanish copy.
