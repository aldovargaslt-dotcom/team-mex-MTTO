## Objective

Convertir `/unidades/:id` en un expediente de Mantenimiento con una acción principal contextual, cuatro secciones, comparación Preventivo/Correctivo, cadencia, historial navegable y foto 4:3 correcta.

## Scope

- Matriz de CTA por rol/estado/borrador.
- Secciones Resumen/Datos/Mantenimiento/Historial responsive.
- Comparación sobre todo el historial cerrado, estados 0/1/2+ y cadencia.
- Filas históricas completas navegables con trabajos/piezas disponibles.
- Render 4:3 y reapertura del editor de reemplazo para Admin.
- Mapeo compartido `PREDICTIVO` → `Preventivo`.

## Out of Scope

- Segundo wizard, Flota/Logística/patio, timeline global, endpoint analítico, historial de fotos, focal point, ranking de flota MTTO, Andon reincidencia o cambios a Health.

## Domain Rules

- Borradores no cuentan; orden descendente; todo el historial cerrado.
- La comparación es descriptiva, no una evaluación moral.
- Foto Kernel; edición solo Admin; Supervisor solo lectura.

## Constraints

### Architecture

Use hub history already available; no cross-schema read or API expansion without escalation.

### Compatibility

Keep order-detail routes and existing unit edit/photo contract.

### Security

Admin-only edit/photo remains enforced by API and UI.

### Performance

Client computation only for v0 full history. Escalate before pagination/aggregation changes semantics.

### UX

Pattern 5, one primary action, accessible comparison, active section visible, rows ≥44 px.
