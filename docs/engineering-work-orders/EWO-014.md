## Objective

Evitar bloqueos silenciosos y sensación de interfaz rota durante cargas en las superficies de Órdenes y ficha de unidad, con validación accesible y skeletons que preserven el layout.

## Scope

- Resumen e indicadores inline de campos obligatorios faltantes en `Nueva orden` y pasos editables del wizard.
- Semántica crítica del inventario de faltantes al cerrar, sin convertir `BORRADOR` en error.
- Primitiva compartida de skeleton estático y estados específicos para `/ordenes`, detalle, selector, `/unidades/:id` y carga inicial del wizard.
- Error recuperable y transición correcta loading → normal/empty/error.
- Evidencia responsive y con latencia simulada.

## Out of Scope

- Endpoint global de Órdenes, cambios API, caché/persistencia offline, rediseño de formularios, skeletons en Inventario/Andon/Flota/Logística o métricas de producción.

## Dependencies

- Aprobación explícita de la adenda SPEC, adenda UX y este EWO.
- EWO-012/013 implementados como base.

## Acceptance Criteria

SPEC AC-L01–L06.

## Testing Requirements

- `cd web && npm run lint`
- `cd web && npm run build`
- Click-through Supervisor a 390×844, 1024×768 y 1440×900.
- Teclado: submit vacío, foco al primer inválido, corrección progresiva y reintento de carga.
- Latencia simulada para carga inicial y cambio de orden; error forzado y respuesta vacía.
- Detector mecánico Impeccable una vez al completar UI; después `proof-ui` y pase independiente `ux-auditor`.

## Constraints

### Architecture

Visual/interacción web únicamente; no tocar `api/src`, contratos ni ownership.

### Compatibility

Conservar rutas, datos capturados, creación atómica y estados `BORRADOR`/`CERRADO`.

### Accessibility

No depender solo de rojo; resumen + mensajes asociados; foco determinista; carga anunciada una vez y skeleton decorativo oculto al árbol accesible.

### Performance

No afirmar reducción de latencia sin medición. No añadir dependencias, shimmer, timers largos ni duplicar solicitudes.
