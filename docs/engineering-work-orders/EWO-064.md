# EWO-064 — Habilitación de Análisis en la aplicación publicada

## Estado y autorización

Implementado y publicado; ver evidencia EWO-064. El propietario reportó «no veo la vista en analisis» después de
solicitar push a main y confirmó que usa team-mex-mtto-eight.vercel.app. Autoriza
corregir la entrega para que la vista publicada esté disponible en ese entorno.
Este seguimiento sustituye la retención de activación de EWO-063 para la
capacidad de análisis solicitada; no amplía permisos, scopes ni lógica operativa.

## Causa y corrección

El commit estaba desplegado pero el catálogo ocultaba Análisis salvo flag de
build=true, variable no entregada. API de Railway correspondiente al mismo
commit tampoco tenía flags, firma estable ni preparación del esquema analítico.
Docker web no declaraba el ARG público para incorporar esa variable en Next.

- Navegación visible por defecto para los roles ya autorizados; false permite
  ocultarla explícitamente. Docker incorpora el argumento durante build.
- Migración aislada de17tablas propias con ledger y FKs propias, sin sync/drop,
  usando el runner revisado de EWO-063. Verificar base efectiva antes de up y
  postflight; ninguna mutación de órdenes, viajes, stock, firmas o scopes.
- Configurar firma aleatoria estable de32bytes y habilitar READ/WRITE/SCHEDULE
  en API del proyecto/entorno verificados. No publicar el secreto en evidencia.
- Publicar Vercel por main y comprobar su despliegue; reactivar API solo después
  de preparar su esquema. No fabricar movimientos financieros en producción.

## Validación / recuperación

Web lint/build sin el flag, y comprobación por roles en navegador. Suite de
integración de análisis en PostgreSQL descartable ya cubre up/down vacío, rechazo
de down con evidencia, idempotencia y firma requerida en producción. Repetir al
preparar release. Activar sin schema/firma debe seguir fallando de forma cerrada.
Si falla, mantener flags deshabilitados; no down ni restauración destructiva de
historia. Evidencia en docs/evidence/EWO-064.md.
