## Implementation and schema

Added canonical type/status/version, assignment/lifecycle foundation, independent blocking/reinspection fields, actor attribution, legacy draft slot and request-idempotency metadata. `source_check_id`/`finding_id` are reserved opaque fields only. No parallel WorkOrder, findings, storage, signatures or physical-state implementation.

`check_inspections` has a one-to-one primary/FK to Visita; deferred constraint triggers reject committed missing, deleted or moved subtypes and reject a subtype on maintenance. `facilities` and `vehicle_facilities` hold explicit configuration/versioning, all within public ownership. No cross-module joins/FKs were added. Mexico City local day boundaries use timezone-aware calendar calculation, including historic DST, rather than a 24-hour TTL.

Active states are PENDING/ASSIGNED/IN_PROGRESS. A service precheck and PostgreSQL partial unique index enforce exclusivity; no process mutex. `ACTIVE_CHECK_ALREADY_EXISTS` contains winning ID/folio/status/step/assignment/start/anomaly/deeplink. The 23505 path waits for transaction rollback, reauthorizes and loads the winner through the root manager. Only the exact CHECK index maps to that error. A terminated winner returns `CHECK_CREATION_CONFLICT` with refresh guidance, without silently creating another. Winner details also require the CHECK's recorded facility after vehicle remapping.

Legacy create retains 201 CREATED/200 EXISTING_DRAFT and its own unique draft slot. Canonical maintenance does not occupy it. Existing driver/unit/km validation and VisitaCerrada envelope remain. CHECK cannot be read/mutated/closed through legacy Visita endpoints and is excluded from maintenance history, hub drafts, ultimoKm and cadence inputs. CHECK create/read do not mutate inventory/outbox/Andon/Salud. CHECK completion routes are absent. Historical maintenance seed timestamps now mirror `completedAt`; no CHECK or production facility seeds were added.

## Security and configuration

AuthenticationPort/TrustedActor and MECANICO are implemented. Canonical APIs obtain subject/name/roles/facility scopes from the server adapter, never browser identity headers. Production startup rejects missing/untrusted/stub adapters. Production legacy requests also use trusted identity; existing header-based legacy behavior remains only outside production.

Default canonical authentication is unconfigured and denies access. Development requires both explicit `NODE_ENV=development` (or test) and `AUTH_MODE=DEVELOPMENT_STUB`; `AUTH_STUB_ACTORS` is a server-managed JSON token→actor map with subject/displayName/roles/facilityScopes. Bearer tokens map to NON_PRODUCTION attribution. This is not a real identity provider. Test fixtures override the port with a trusted test double only.

Facility mappings are configured explicitly through the owner tables; missing mapping returns 422 FACILITY_CONFIGURATION_REQUIRED. There is no fallback facility or production seed. A shared row lock protects the mapping during creation. The physical-state read port is a contract only, returning KNOWN enum4 or null UNAVAILABLE/UNINITIALIZED; no adapter/state machine.

## Recovery and operational limits

Only disposable fixtures were migrated. For another authorized disposable rehearsal: verify effective connection/disposability, clear DATABASE_URL, supply the isolated fixture schema, explicitly set both schema flags false, EWO_DISPOSABLE_DB=true and matching MIGRATION_DISPOSABLE_DATABASE; stop all old writers/bootstrap processes before setting CHK_LEGACY_WRITERS_DRAINED=true; run `npm run migration:up`. The runner rejects production and mismatching/non-test database names.

M001–M006 run in one transaction for this rehearsal; audit failure rolls back expansion/backfill. Replacement indexes/triggers exist and are verified before old global protection is retired. The drain variable is an **operator attestation**, not automatic process/replica discovery. A future rollout needs actual maintenance/drain coordination and independent release authorization. Do not start an older synchronize/bootstrap binary against the migrated schema.

`npm run migration:down` undoes one version, and every down checks rollback safety. New canonical rows, mutations or facility configuration return FORWARD_RECOVERY_REQUIRED. Do not delete such rows/configuration to force rollback outside disposable fixtures. Disable affected writes and recover forward; preserve original identity/history. A legacy-only untouched fixture roundtrip is tested. Disposable container cleanup removes only the named EWO container/tmpfs; no user database is a cleanup target.

Known limits: no production identity provider, real facility configuration, scheduler, condition/PSI, storage, findings, signature, CHECK completion/invalidation, physical-state implementation, insurance, Tower, urgency or movement authorization. The CHECK conflict step/anomaly fields are null because those later slices are absent. N-maintenance and legacy APIs are backend foundations; no new UI. No production deploy/migration or EWO-016 work.

Deviations: no product/domain scope deviations. Environment used cloud Docker PostgreSQL because native PostgreSQL/sudo and local Docker were unavailable/excluded. Next build used its supported system CA option for the managed proxy. Optional request idempotency and M006 are within the approved contract/plan. Node 20 hosted CI is reported separately from Node 24 local validation.
