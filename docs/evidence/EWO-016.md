## Runtime configuration and limitations

- Daily is disabled unless `CHECK_DAILY_ENABLED=true`. Explicit `CHECK_DAILY_SCHEDULES` JSON entries require `facilityId`, `localTime` (`HH:mm` in America/Mexico_City), `actorSubject`, `actorName`; invalid enabled configuration refuses startup. Polls every 60 seconds, invoking only the shared command after the configured local time. Multiple invocations/replicas remain ledger-idempotent.
- The default physical-state port explicitly returns UNAVAILABLE. Real Flota physical-state provisioning belongs to a later slice; daily remains disabled or skips `PHYSICAL_SOURCE_UNAVAILABLE`, never inferring EN_PATIO from journeys/maintenance. Schedules, actors and mappings in tests are fixtures, not production settings.
- CHECK delivery defaults enabled, polling every 30 seconds (test timers disabled); `CHECK_DELIVERY_ENABLED=false` pauses delivery without dropping pending events. `runOnce()` returns delivered/failed counts. Re-enable/retry to recover pending delivery; eventId prevents duplicate inbox items.
- Canonical authentication remains the EWO-015 trusted server port. No production identity provider was selected or installed. Browser calls preserve same-origin credentials; the existing role picker does not authenticate canonical requests. Browser proof used an explicitly configured nonproduction bearer injected through Chromium CDP into the real development adapter. A real trusted browser/session integration remains a deployment prerequisite. Without trusted credentials, canonical requests fail closed.
- Read page intentionally has no later-slice technical actions. Missing assignment name, step or anomaly data is not fabricated. An IN_PROGRESS browser fixture used a stored real `started_at`; no product transition/claim endpoint was added.
