## Implemented

- Capacidad documental mínima `POLIZA_SEGURO` en schema `vehicle_documents`: fecha `DATE`, historial append-only, versión/current, `expectedVersion`, actor y referencia a la versión sustituida.
- Escritura documental sólo Admin y lectura Admin/Logística/Mecánico mediante `TrustedActor`; documento y Torre validan `facilityScopes` server-side.
- Fuente física Flota explícita con `EN_PATIO`, `EN_RUTA`, `EN_TALLER`, `INACTIVA`, ledger/version y origen. Una correctiva no infiere taller.
- `GET /logistica/torre-control` compone en batch Estado físico / Habilitación / CHECK / Urgencia, admite los cinco filtros/cursor/límite y calcula conteos distintos dentro del mismo scope autorizado.
- Readiness falla cerrado por póliza, fuente física o configuración; una unidad en ruta conserva `DESPACHADA` y muestra causas críticas.
- Urgencia usa configuración persistida, máximo de causas y bordes exactos: 0 sin causa, 2 h `ATTENTION`, más de 2 h `CRITICAL`.
- Dashboard `/logistica` responsive con conteos, `asOf`, stale source, filtros, refresco manual/60 s, reasons expandibles y filas móviles densas.

## Database / Security / Recovery

La verificación formal usó PostgreSQL 16 local en Compose, `DATABASE_URL=''`, `DB_NAME=team_mex_mtto_test`, `DB_DROP_SCHEMA=true` y `EWO_DISPOSABLE_DB=true`. No se usaron credenciales ni targets externos. La prueba visual usó un actor `DEVELOPMENT_STUB` configurado server-side y mappings de facility sólo en la base desechable; los valores no son configuración productiva.

Durante la preparación visual hubo un arranque local anterior con `DB_DROP_SCHEMA=true` sin fijar `DB_NAME`; eso reinicializó y resembró la base Compose local `team_mex_mtto`. No afectó una base externa, pero el contenido local previo no es recuperable desde esta sesión porque no se tomó backup. Los runs formales posteriores fijaron explícitamente `team_mex_mtto_test`.

La migración `1790899200012-ControlTowerReadiness` crea `flota.physical_state_events`, `vehicle_documents.document_versions` y `alertas.torre_urgency_config` con índices/constraints. El rollback estructural se validó en la suite de migraciones; no se aplicó a producción.
