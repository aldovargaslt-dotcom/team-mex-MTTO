### Fallo descubierto y corregido

La prueba real claim → start → condición → subir dos PNG → REQUIRES_WORK →
review → firma devolvía 500: `visitas_legacy_mirror_ck` rechazaba la correctiva
con estado legacy null. La fábrica ahora usa BORRADOR/CORRECTIVO conforme al
espejo de mantenimiento definido en contrato/backfill. Se mantienen canónicos
CORRECTIVE/PENDING, legacy_compat_draft=false, sin nuevas reglas de programación,
roles, estados, efectos Flota ni migraciones. La restricción exige BORRADOR para
mantenimiento activo; CORRECTIVO conserva el tipo legacy correspondiente.

`api/test/fixtures/check-images.ts` produce un PNG sintético de trazo; los tests
usan un mkdtemp exclusivo y el adapter de filesystem privado real, eliminan solo
ese directorio y restauran los límites de prueba al terminar.
