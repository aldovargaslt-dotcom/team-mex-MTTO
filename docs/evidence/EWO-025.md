# Evidencia EWO-025 — Panel de usuarios

Autorizado por usuario: panel de administración de usuarios con administrador
inicial y asignación de accesos. SPEC-AUTH-002 / ADR-021 / UX usuarios-admin-v1.
Baseline `ddd1ac8`; preservados EWO-023/024 sin commit ni PR.

## Implementación

Kernel/Auth posee `auth.users` y `auth.user_audit`, sin FK/JOIN cruzadas.
FacilityDirectoryPort consulta los patios existentes. OIDC verifica firma y claims
antes de resolver por issuer+subject. CONFIG conserva EWO-024; DATABASE lee cada
solicitud sin caché ni fallback a mapping/headers. Bootstrap importa sólo en
directorio vacío, exige administrador y patios válidos y audita la importación.

GET/POST `/admin/users`, GET options/audit y PATCH por ID sólo Admin confiable.
Altas y cambios auditan antes/después/ejecutor/fecha en misma transacción; lock
compartido protege último Admin y revalida permiso del ejecutor. Versión requerida
impide pérdida de actualización. Subject inmutable, roles existentes sin SYSTEM,
patios del catálogo; no contraseñas locales ni invitaciones simuladas.

UI `/configuracion/usuarios`: búsqueda/estado, listado→formulario, roles y patios,
activar/desactivar con confirmación, errores y reintento. Se reutiliza
ConfiguracionNav y RoleGate, sin añadir kit, tokens ni permisos de dominio.

Pruebas negativas: browser-only identity, claims con Admin, no provisionado,
mecánico 403 aun con header Admin, duplicates, SYSTEM, patios inexistentes, roles
vacíos, campos desconocidos, activo string/null/missing en edición, versión
obsoleta, subject mutable, último Admin y concurrencia de desactivaciones.
Revocar/reactivar con mismo JWT cambia acceso inmediatamente. Restart no importa
mapping otra vez; bootstrap sin Admin o con patio inválido revierte toda importación,
bootstrap concurrente importa una vez, error DB niega acceso sin fallback.

Primera suite unitaria encontró dependencia DB accidental en TrustedAuthModule:
3 tests fallaron. Se separó UserAdministrationModule global mediante puerto
opcional; CONFIG/stub aislados siguen sin DB. Repetición: 239 tests PASS.

Recorrido con Mecánico detectó copy incorrecto (incluía Logística) del RoleGate:

## Alcance de fixtures y pendientes

Proveedor OIDC sintético HTTPS con PKCE/state/nonce y JWT firmados; aplicación
verifica TLS con CA local agregada, sin desactivar TLS en Node. Chrome ignora
sólo certificado local del fixture. API Auth usa módulos/controladores/services,
TypeORM y PostgreSQL reales; las vistas vacías de otros dominios permiten llegar
al panel, no prueban sus operaciones. Harness limpia schema Auth e historial sólo
en base desechable confirmada; no ejecutarlo simultáneamente con E2E.

Falta elegir/configurar proveedor y cuentas/subjects/patios reales, ejecutar
migración revisada en entorno autorizado y verificar staging. El panel vincula
cuentas OIDC ya existentes; alta externa e invitaciones requieren la API del
proveedor. Guía: ../design/usuarios-admin-staging.md.

No cambia permisos pendientes de Mecánico sobre mantenimiento/preventivos/tickets/
liberación. CHECK y Mantenimiento siguen separados. No commit, PR ni despliegue.
