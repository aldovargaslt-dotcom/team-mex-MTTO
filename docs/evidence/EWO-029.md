# EWO-029 — Evidencia de Docker local Windows

Verificación previa a publicación realizada en el workspace cloud. No instalado
en la PC del usuario, no desplegado en Railway ni Windows. La publicación del PR
se autoriza en el seguimiento del usuario: «Este setup lo podrias hacer tu?».

## Resultados

- PASS — `docker compose --project-name team-mex-mtto -f docker-compose.yml -f compose.local.yml --profile app config --format json`.
  Se verificó el JSON resuelto: tres puertos limitados a 127.0.0.1, targets
  development para API/web, API_URL=http://api:3001, DB_DROP_SCHEMA=false y volumen
  Postgres persistente (AC1, AC2).
- PASS — `docker compose -f docker-compose.yml --profile app config --quiet`.
  El Compose base sigue siendo válido; los targets runner de producción siguen
  al final de ambos Dockerfiles como defaults.
- PASS — YAML de Verify y Deploy local Windows leído con PyYAML BaseLoader y
  aserciones de triggers PR/main, workflow Verify, opt-in, éxito, evento push,
  repo de origen, SHA verificado, runner Windows y serialización (AC3, AC4 parcial).
- PASS — revisión del script: comandos Docker fallan con exit no cero, build
  antecede up, up usa --wait, no hay down/prune/restore/migraciones. La consulta
  autenticada del ref main omite SHAs anteriores. No equivale a ejecución real.
- PASS — guía de instalación, activación, pausa, backup sin redirección binaria,
  límites de identidad y synchronize; README enlaza el camino Windows (AC5).
- PASS — `git diff --check`.
- SKIPPED — build/arranque Docker: la consulta explícita al socket administrado
  devuelve `connect: operation not permitted`. Compose config no necesita daemon.
- SKIPPED — ejecución/parseo nativo PowerShell: `pwsh` no instalado en este
  executor Linux. Requiere smoke test en Windows con PowerShell 7.
- SKIPPED — actionlint no instalado; `go install ...@v1.7.7` no disponible con el
  wrapper Go del entorno (`Go: Unknown option: install`). YAML/condiciones sí
  comprobados, sin declarar validación nativa de GitHub Actions.
- SKIPPED — tests API/UI: sin cambios de fuentes, contratos, reglas o pantallas;
  Verify existente continúa haciendo API unit/e2e/migrations y web lint/build.

## Handoff

AC1/AC2/AC3/AC5 verificados como configuración/documentación. AC4 conserva
verificación parcial: falta ejecutar en Windows el script, verificar salud y
realizar un merge con CI exitoso que active el runner. No se declara verificación
completa ni instalación del CD. La sincronización de esquema sólo corresponde
a la base local de desarrollo; no se autoriza restaurar/sincronizar producción.
