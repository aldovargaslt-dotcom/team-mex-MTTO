## Resulting behavior

- New departures save a stable journey, exact existing departure audit and unit
  state together, preserving current policy and driver validation.
- Return records matching endpoint, trusted actor/auth provenance and facility
  mapping versions before clearing the unit's departure timestamp/pointer.
- Durable receipts plus unit/journey expectations prevent duplicate endpoints and
  stale return against a later trip. Expected subject is an equality precondition;
  authentication alone supplies attribution.
- Explicit missing-history states support genuine legacy return without fabricated
  driver, actor, departure time, audit or revision. Capture epochs retain original
  provenance across a later coverage epoch.
- Existing non-lifecycle writers patch permitted fields and coordinate relevant
  changes. Seed/bootstrap preserves trips and guards captured placeholder cleanup.
- Both existing return callers and departure caller use stored command envelopes;
  BFF preserves every binding header. Confirmed pending envelopes may automatically
  execute their first commit after reload, exactly as owner decided.
- GET /health/ready verifies schema/capture without creating facts. /health remains
  liveness. No business readiness gate or Flota custody change was added.
