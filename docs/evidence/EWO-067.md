Worker model: not recorded (agent session).

## Deviations

- **Capture tooling.** The repo says `proof-ui` does not use Playwright and agents use a browser or computer use. This session has neither, so screenshots were taken with the sandbox's preinstalled Chromium driven by scripts kept outside the repo. No dependency was added to `web/`.
- **Local identity.** In local development the web client sends only `X-Role`, but order, readiness and check endpoints require a verified actor, so they return 401 and the app sends the user back to the role picker. For the screenshots only, the API ran with `AUTH_MODE=DEVELOPMENT_STUB` and an actor, and the capture browser added a `Bearer` header. The red "No pudimos confirmar la operabilidad" panel in one ficha screenshot comes from that local setup, not from this change.
- The unit list's "Nueva unidad" link was not clicked in the capture; the create form was opened by URL after logging in through the role picker.

## Known Limitations

- **The seed migration runs on production automatically at the next deploy.** `api/railway.toml` runs `run-ui-release-migrations.js` as `preDeployCommand`, and the migration is registered there. It is additive and idempotent (9 rows, `monterrey` untouched). Merging/deploying remains the Owner's decision.
- **Existing units stay without a sucursal until [EWO-068](../engineering-work-orders/EWO-068.md).** Production check by the Owner on 2026-11-07: 14 units, 0 mapped; one facility, `monterrey`.
- Until then, editing an existing unit requires choosing a sucursal (the field is required), which assigns it.
- Per-facility timezone is deferred by the Owner to the CHECK work; border sucursales may need another zone.
- The Chromium check was done on the local development stack, not on a deployed environment with OIDC.
- **A fresh local database has no sucursales.** The seed lives in a migration that only the release runner applies. A database created with `synchronize` (local development, e2e) does not run it, and the demo seed creates no facilities. With the field now required, a developer cannot create a unit locally until sucursales are inserted by hand (as done for the screenshots). Tracked in [EWO-069](../engineering-work-orders/EWO-069.md).

## New Decisions Discovered

- **Catalog read.** The form reads sucursales from a new `GET /unidades/sucursales` (ADMIN_DIRECTIVO only) in the units module, instead of reusing `/admin/users/options`. This was the UX spec's stated preference but was left open in EWO-067's escalation conditions. Owner to confirm.
- **Nuevo Leon shows as "Monterrey".** The existing production facility is `monterrey` / "Monterrey" and the Owner chose to keep it unchanged. Changing the display name is a one-line data change with no id change.
