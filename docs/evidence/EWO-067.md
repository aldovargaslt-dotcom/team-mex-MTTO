## Deviations

- **Capture tooling.** The repo says `proof-ui` does not use Playwright and agents use a browser or computer use. This session has neither, so screenshots were taken with the sandbox's preinstalled Chromium driven by scripts kept outside the repository. No dependency was added to `web/`.
- **Local identity.** The first captures ran with a stub actor and a `Bearer` header added by the capture browser. The re-capture used `bash script/dev-local.sh` ([EWO-069](../engineering-work-orders/EWO-069.md)) on a fresh database, with no injected header.
- **"Reintentar" variant.** The spec said `secondary`; the shared `ReadStatus` component renders an outline button. The shared component was reused on purpose and the spec text is updated to say so.
- **Warning layout.** The change warning sits inside the Sucursal cell, so on desktop the Estado cell beside it stays empty for that row. The independent reviewer judged it acceptable; left as is.

## Known Limitations

- **The seed migration runs on production automatically at the next deploy.** `api/railway.toml` runs `run-ui-release-migrations.js` as `preDeployCommand`, and the migration is registered there. It is additive and idempotent (9 rows, `monterrey` untouched). Merging/deploying remains the Owner's decision.
- **Existing units stay without a sucursal until [EWO-068](../engineering-work-orders/EWO-068.md).** Production check by the Owner on 2026-11-07: 14 units, 0 mapped; one facility, `monterrey`.
- **A unit without a sucursal shows a red "No pudimos confirmar la operabilidad" panel in its ficha.** This is real and not caused by the new field: without the unit↔facility link `GET /unit-readiness/:id` answers 404 "No se encontró una unidad autorizada" (checked against a healthy local API; the same unit with a sucursal answers 200). It is the same root cause as the original failure, so it should disappear once EWO-068 runs. An earlier version of this file wrongly blamed the local setup for it.
- Until then, editing an existing unit requires choosing a sucursal (the field is required), which assigns it.
- Per-facility timezone is deferred by the Owner to the CHECK work.
- The select has no `aria-describedby` linking it to the warning, error or empty text. The messages are announced (`role="status"`/`role="alert"`), so this is advisory.
- A fresh local database had no sucursales; fixed by [EWO-069](../engineering-work-orders/EWO-069.md).
- Checked on the local development stack, not on a deployed OIDC environment, and not at 1024 px.

## New Decisions Discovered

- **Catalog read.** The form reads sucursales from a new `GET /unidades/sucursales` (ADMIN_DIRECTIVO only) in the units module, instead of reusing `/admin/users/options`. This was the UX spec's stated preference but was left open in EWO-067's escalation conditions. Owner to confirm.
- **Nuevo Leon shows as "Monterrey".** The existing production facility is `monterrey` / "Monterrey" and the Owner chose to keep it unchanged. Changing the display name is a one-line data change with no id change.
