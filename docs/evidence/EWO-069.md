# Evidence — EWO-069

## Summary

Engineering Work Order: [EWO-069](../engineering-work-orders/EWO-069.md) — Entorno local completo.
Worker model: not recorded (agent session).
Verifier result: PASS on all acceptance criteria and gates. No UI component changed, so the UI review chain does not apply; click-through evidence is attached. Not deployed.

Before: in local development the web client sent only `X-Role`, so endpoints that need a verified actor returned `401` and the app went back to the role picker, and a fresh local database had no sucursales, so a unit could not be created. Now `bash script/dev-local.sh` starts everything and every role works on a fresh database.

## Acceptance Criteria

### AC-1 — PASS
A new empty database (`team_mex_fresh`) and `bash script/dev-local.sh`. Each role chosen in the role picker with a plain browser (no injected headers), then its screen:

| Role | Screen | Backend statuses | Back at picker |
|---|---|---|---|
| Supervisor | `/ordenes` | 200 ×36 | no |
| Administrador | `/unidades` | 200 ×8 | no |
| Logística | `/flota` | 200 ×6 | no |
| Mecánico | `/mi-trabajo` | 200 ×4, 403 ×2 | no |

No `401` anywhere. The two `403` are `GET /notifications/badge` for the mecánico role, an existing role restriction unrelated to this change.

### AC-2 — PASS
Fresh database after the first start: 10 facilities; 13 units, 13 mapped. `dev-facilities.e2e-spec.ts` also proves idempotence.

### AC-3 — PASS
In the browser on the fresh database: the administrator created unit `DEV-LOCAL-1` choosing Reynosa and the ficha shows it; a supervisor then created an order for it (`POST /unidades/:id/mantenimiento-ordenes` → 201) and landed on the order wizard. This is the flow that failed with 422 at the start of the investigation.

### AC-4 — PASS
Unit tests for every non-development value plus the e2e boot check (zero facilities and mappings when `NODE_ENV` is not `development`).

### AC-5 — PASS
Existing `api/src/auth/trusted-actor.spec.ts` covers the refusal of `DEVELOPMENT_STUB` outside development/test; it ran green. Not modified.

### AC-6 — PASS (manual, not automated)
`developmentToken` was run with Node for each case: `NODE_ENV=production` → `null`; `test` → `null`; development with OIDC mode → `null`; development without a prefix → `null`; development with an invalid role → `null`; development with prefix and role `SUPERVISOR` → `"dev-SUPERVISOR"`. The production branch of the proxy is unchanged and still requires the session cookie. `web/` has no test runner, so this is not in CI.

### AC-7 — PASS
README "Cómo correrlo" and `.cursor/environment.json` use `script/dev-local.sh`; the manual steps remain as the same path, no new one.
